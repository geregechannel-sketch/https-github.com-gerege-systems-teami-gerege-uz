# Transactional TEAMI archive storage

`teamisource.Store(ctx,pool,request,mapping,body)` accepts an already obtained source archive JSON response, not HAR files, cookies or authentication headers. It is an internal integration function, not a public import endpoint. No scheduler, network login or production writes are enabled.

Mapping must explicitly supply source reference, target point/ML/MD/AGGS, unit and source timezone. The target point must exist. The caller is responsible for independently verifying these choices against source metadata and target configuration. Positive IDs are not proof that a mapping is correct. No default timezone or source/target ID equality is assumed. Only the captured query flags are accepted.

The decoder validates the source point/ML and timestamps. Store checks every interval against the requested source calendar range and converts timestamps using the explicitly supplied timezone. Null VAL rows are retained in the full source receipt but not inserted into the numeric sample table. A genuine numeric zero remains zero. Exact numeric text is passed to PostgreSQL NUMERIC without float conversion.

A transaction and per-target-series advisory lock protect each batch. New samples are inserted. Existing keys are accepted only if value, interval end, unit, status, source reference, raw row, source read time and timezone agree. A conflict, timeout or storage error rolls back the entire batch including any newly inserted rows and receipt. Corrected values or changed metadata require an explicit reconciliation policy; there is no silent overwrite. Other writers that do not follow this lock can still modify data, so this is not global database immutability.

Source receipts bind the request, mapping, timezone name and range offsets to the captured response using SHA-256. Exact retries reuse the same receipt; differently serialized responses may retain another receipt while numeric samples remain deduplicated. All response rows, including missing intervals, are retained as JSONB. UPDATE/DELETE/TRUNCATE on receipts are rejected by a database trigger, subject to the same owner/superuser bypass limitation as audit records. Receipt retention and source authenticity are not cryptographically established by a hash alone. The existing application owner role and historical migrations still require deployment review.

PostgreSQL integration tests cover source/target ID separation, decimal preservation, explicit timezone conversion, missing-versus-zero semantics, repeat imports, complete rollback after a late conflict, receipt retention, period rejection and authenticated local-API reads of the stored rows. Fixtures use fabricated test IDs and values in the CI database only.

Before live enablement: verify source timezone and mappings; provision authentication on the integration host without copying HAR credentials; connect an authorized read-only collector; add scheduling, retry/backoff, operational failure logging and retained checkpoint management; deploy through reviewed migrations and reconcile a newly received real interval against TEAMI. This commit alone is not proof of an automatic production connection.
